# OIDC issuer 与身份归属

独立分支 `codex/oidc-issuer-ownership`，基于 PR #81 已合并 main
`416a52ea533131d1f64f29efb3764c9c775bb489`。不依赖未合并的 Realtime、Rollup 或 Vite 草稿。
本项实现已验证的 issuer/subject 归属、并发新注册唯一性和保守历史迁移；不实施生产恢复。

## 已确认的问题与正常行为

旧回调验证 token 后仍只按 subject 选取首个活跃账号，未保存 issuer；不同的合法 issuer
使用相同 subject 时会共用本地身份。历史重复记录也会任意选取首项。
注册先查询再插入，缺少身份唯一约束，两个独立请求可各自创建账号。

本地自签合成 IdP 使用拒绝未知目标的进程内 HTTP transport，临时 SQLite、不联系真实身份平台。
旧版跨 issuer、历史 issuer 未知、历史重复、软删除身份重新分配四项失败；新注册、同 issuer
登录和缓存 verifier 三项正常控制通过。另一个旧版交错测试中，八个相同 subject 的注册都成功，
期望单一归属失败；八个不同 subject 的正常对照通过。

## 共享身份边界

- 保存原始 subject、已验证 issuer 和 nullable 唯一身份键。身份键为明确长度分隔的
  issuer/subject 的 SHA-256；命中后仍核对原始字符串，避免数据库排序规则改变身份语义。
- issuer 来自当前 verifier 验证后的 token，只有该 verifier 对应的 Google 特定别名沿用
  go-oidc 的兼容规则；不使用回调时可变的配置回填，不对其他 URL 做通用归一化。
- 用户与唯一身份键在同一次 INSERT 创建。只有胜出 INSERT 产生初始额度和注册记录；
  竞争失败只可读取精确、未删除的同一身份，控制器再次核对启用状态。
- 普通 User.Update 排除全部三个 OIDC 字段，通用新用户 Insert 拒绝不完整身份。
  管理员资料 JSON 不能写入 issuer/身份键，也不能用单独 oidc_id 新建未验证绑定。
- 明确解绑在一次更新中清空 subject/issuer/身份键，可以随后重新注册该身份；
  软删除保留身份占用，不能作为解绑或迁移批准。既有 session 撤销规则未扩大。

## 保守迁移与失败处理

用户已明确选择：未知历史归属保留待核实，不自动关联。
新增列和索引沿用现有 User AutoMigrate；原 subject、不明 issuer、重复记录均保留，
身份键保持 NULL。没有按当前配置、首次登录、相同用户名或记录顺序选择历史所有者。
相关旧 OIDC-only 账号需独立核实和恢复；其他登录方式保持现有规则。

已验证的新 issuer/subject 可以注册独立账号，但相同原始 subject 的历史未知记录会阻止
自动分配。数据库排序规则可能匹配大小写或尾空格相近的文本，最终仍按原始字符串判断。
缺列、缺身份索引或索引创建失败时 OIDC 拒绝继续，不回退到旧 subject-only 查询。
迁移失败由现有 InitDB/SetupDB 错误路径阻止启动；从节点或中断迁移的运行时查找同样核对索引。
没有历史回填脚本、管理员自动恢复入口或对生产数据库的读写。

完成，后续历史行扫描会把完整新身份误判为未知。确定性交错测试复现后，补丁仅让该扫描
接受完整、精确、未删除的匹配身份，并将新增测试纳入三数据库入口。

## 升级、回退与保留事项

新增字段对非 OIDC 用户保持 NULL/空值，允许多个未绑定账号。新增字段不通过用户 JSON 暴露。
旧程序即使能读取新增 schema，也会恢复 subject-only 登录逻辑，且旧解绑不会同步清理新身份键；
因此 schema 可读取不等于身份回退安全。回退期间必须关闭 OIDC，并经独立核对再恢复；
不要自动删除身份键或回填旧数据来让旧程序继续登录。

真实历史归属恢复、真实 IdP/生产配置与凭据核实、生产升级回滚仍未验收。RC8 仅预留；
没有标签、镜像发布、生产部署或真实付费调用。
