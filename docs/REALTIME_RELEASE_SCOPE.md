# 首版暂不提供 Realtime

2026-10-02，维护者明确批准首版暂不提供 `/v1/realtime` 双向实时语音，保留普通聊天和SSE。
本项从 `f48f5fab1f5dac238511d8c1b644faf134c2aeee` 独立开发，不合并或依赖 #78/#79。
**这是发布功能范围限制，不是底层Realtime解析、计费或恢复缺陷已经修复。**

## 行为和边界

- `GET /v1/realtime` 固定返回 HTTP501、OpenAI风格JSON错误：
  `error.type=one_hub_error`、`error.message=realtime_disabled_for_release`。
- 该路由注册在认证/分发/限流中间件组之外：不校验令牌、不建立WebSocket、不预留额度、
  不选择渠道或连接上游。全局CORS和一般请求日志仍按原配置执行；预检响应不表示功能开启。
- 没有环境变量、后台选项或配置开关可以重新开放此入口。恢复功能需要后续代码变更、
  独立审阅、正常与故障路径验收，以及明确的功能范围批准。
- 普通 `POST /v1/chat/completions` JSON/SSE、Responses及独立语音转写/翻译/合成路由保留。
  关闭双向Realtime不等于关闭所有语音API。
- 底层Realtime实现和原有回归保留；它不再从当前生产路由注册到HTTP入口。
  未注册的方法/子路径沿用原有未匹配路由处理，尾斜杠重定向后仍进入禁用端点。

仅在handler内部提前返回不足以满足本项：前置认证会查询数据库，Redis关闭时还可能
更新耗尽令牌状态。直接删除路由也会随嵌入前端/外置前端配置产生不同未匹配行为。
因此本批保留明确的拒绝端点，放在这些副作用之前；其他认证规则未放宽。

## 回归与当前证据

同一份最终路由回归在旧版失败：7个入口子例及耗尽令牌检查未得到501；
普通聊天JSON/SSE的认证对照仍通过。候选全部通过并开启race检测。

路由测试使用真实 `SetRelayRouter`，覆盖无凭据、无model、模型参数、无效Bearer、
48字符合成旧令牌、WebSocket子协议凭据、编码路径及尾斜杠重定向。
不启动数据库的用例检查501和无升级响应头；独立临时SQLite夹具确认耗尽令牌请求
产生零GORM查询/更新、令牌状态与额度不变。正常控制直接走旧认证，确认同一夹具会
识别额度耗尽并更新状态，避免使用无效夹具冒充副作用验证。

最初SQLite夹具触发未初始化的当前签名服务创建钩子；随后以SkipHooks插入明确的
48字符旧格式合成令牌，并用真实认证控制验证其有效性。失败设置不记为通过。

镜像验收入口新增匿名、有限额令牌、无限额令牌的实际HTTP检查，断言拒绝前后
额度、预留、消费日志、渠道计费快照和模拟上游计数相同；沿用其后的正常JSON及SSE业务控制。
该检查在SQLite/MySQL/PostgreSQL三种隔离后端执行，候选CI须证明实际运行结果。
新路由race测试和vet已加入兼容性CI。只有合成数据和模拟服务，没有外部模型调用或生产改动。

本地相关回归、独立候选审阅、准确候选CI和合并结果在本项PR最终记录分别补齐，
不得从旧版CI或已合并的文档#126推断本项通过。当前仍是未交付候选。

本地7个相关Go包race回归、路由vet、38项Python夹具检查、发布策略及actionlint通过。
一次fresh、非作者只读候选审阅未发现新入口存活路径或普通聊天回归；指出原测试只比较
两项聊天计数，无法捕获上游拒绝GET的计数变化。作者核对模拟上游后改为比较完整
`/stats`字典，保留拒绝计数，并重跑相关检查；没有以第二轮审阅替代原结论。
镜像业务、三数据库及双架构结果仍须候选CI实际执行后记录。

## 保留项和恢复条件

#78/#79仍保留各自草稿、修正和受限审阅缺口，本批未重试或改道那些步骤。
未知用量、跨连接、崩溃持久性和历史归属不能因此认定已经结算，也不执行自动退款/补扣。
若未来恢复Realtime，需要先完成这些范围的交付决定及验收；不得只删掉拒绝路由就开放。

未部署本候选的实例不会自动获得该限制；旧镜像回退也可能重新开放Realtime，
部署/回退计划必须单独核对该功能边界。RC8仍需其余依赖、最终源码/镜像、新恢复点等验收，
标签、发布、部署及真实付费调用的专项批准不变。
