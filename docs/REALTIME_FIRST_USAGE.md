# Realtime 首帧失败后的已报告用量

本项在响应收据候选 `ba4df832` 上单独处理首帧收尾，交付基线更新至其已合并的
main `b01e0ffc`，源码补丁不变；不改变收据去重或价格算法。
上游 usage 经过完整验证与合并之后，续额或客户端首帧写入仍可能失败。
旧错误分支只检查输入/输出总 token，遗漏明细及内部 extra-only 用量，随后退款并重试。

## 修复边界

`Usage.HasTokenUsage` 复用完整计数列表并检查内部 ExtraTokens；首帧错误分支据此停止
重试并进入既有 Consume。它判断是否已有被接受的正用量，不根据最终费用是否大于零
判断工作是否发生。免费和零分组倍率仍记录零费消费；无法安全计价则保留预留待核对。

没有已接受用量的拨号、协议、空首帧等失败，仍按既有策略退款/重试。负数输入被完整
Merge 拒绝，不会变成已接受用量。正常总 token、按次、有限/无限 token 行为保留。
TotalTokens 或 prediction 等仅报告字段可以停止重试，但不会因此新增这些字段的定价。
仅供应商方向提供计费用量，客户端同形帧不能通过此变化成为收费依据。

## 隔离证据

- 真实 localhost WebSocket 与临时 SQLite 的最终 12 场景：旧版 9 个失败、3 个正常对照
  通过；候选全部通过。覆盖音频续额失败、无限 token 下账户余额不足、音频/推理首帧
  写失败、按次、免费、零倍率、total-only、无效计价保留预留、正常 token 与无用量重试。
- 写失败仅由测试 HTTP 101 完成后的连接包装器注入，不靠真实网络中断或生产钩子。
  每条连接均有读写/清理期限，测试总超时 90–240 秒，不使用真实上游或凭据。
- 内部 extra/cache/prediction、零值及 nil 等 5 个合并控制通过。相关 Realtime/Usage
  专项合计 39 个叶子、45 个节点通过；规定离线包与受影响包 race、策略、vet、编译通过。
  Go 使用 1.25.14，依赖下载关闭。首次临时复制路径错误导致未发现测试，该次不计通过；
  修正路径后的旧版失败日志与最终候选日志分别保留。
- 全新独立只读调查完成。候选四文件补丁 SHA-256 为
  `445f665d89cc90d9283e6e0eecaec25a1b276dbb4a2cc1c9c1d2c532407c4b32`。
  新建审阅者遇到工具线程数上限，转由未参与本项调查或实现的既有审阅者只读审阅；
  上下文复用属于流程限制，不称为全新上下文。审阅者在独立临时副本通过相关 Realtime、
  模型与用量算术 race 测试，并换回旧首帧实现确认 9 个问题场景失败、3 个正常对照通过；
  未发现该四文件候选内存活绕过或阻断回归。准确 CI 与合并仍待记录。

## 未关闭的范围

这证明项目内部收尾分支存在账务缺口，不证明真实供应商经常发出该首帧形式，也不
证明客户端能伪造供应商用量。缺失 usage、进程崩溃、跨连接收据与历史歧义金额仍开放。
无效计价留下的预留不按年龄退款；本项不生成猜测金额或自动人工核销规则。
无 schema 改动；回退会恢复首帧错误退款风险。未创建标签、发布镜像、部署或付费调用。
