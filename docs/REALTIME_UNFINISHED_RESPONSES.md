## 问题与验收边界

旧处理器忽略供应商的 `response.created`。连接关闭或供应商报错后，只按已完成响应
累计用量生成最终费用；首帧写失败且没有已完成用量时，还会退款重试。
已经观察到工作开始但没有相应可接受的完成报告，不能据此证明总费用是零或已有部分。

[官方会话文档](https://developers.openai.com/api/docs/guides/realtime-conversations)
描述开始、增量和最终完成事件；[客户端事件说明](https://platform.openai.com/docs/api-reference/realtime-client-events)
还包含取消及并行的会话外响应。本项按供应商事件建立合成测试，没有调用真实供应商。

## 候选处理

- 供应商专有 `ResponseStarted` 元数据覆盖首帧和后续回调，客户端或 usage JSON 不能设置它。
- 按响应 ID 的 SHA256 跟踪未完成项，最多 1024 个；不存原始 ID 或输出。
  容量耗尽停止会话并保留未知标志，不淘汰旧项以恢复确定结算。
- 仅对应的已接受完成用量清除该项。无关或匿名完成不能清除其他已识别响应，
  重复开始幂等，已完成 ID 的开始重放不重新打开工作。
- 匿名开始不能可靠关联，保守保留未知。没有匿名开始时，原有匿名/首帧直接完成报告
  仍正常收费；完整取消报告的已知费用也保留。
- 接受报告和续额成功分开判断：接受完整报告后续额失败，仍结算该完整报告；
  非法/冲突报告不会清除其余工作。
- 主循环等待双方 worker 停止后、首帧失败关闭上游后，再选择
  `realtime_unfinished_response` 待核对意图；存已知部分及未完成数量，保留预留，
  不写确定账单、不退款重试。复用原不可变快照、归属和恢复边界。

## 保留限制

客户端 inference/VAD 已发送但尚未观察到供应商工作事件的窗口、开始事件缺失但
出现其他进度事件、进程在证据持久化前崩溃、跨连接归属及历史人工核对仍待后续证据。
本项不声称涵盖所有异常结束或持久恢复，不推断真实供应商成本。
没有新增数据库列或真实资金处置接口；回退代码会恢复该错误收尾路径，
必须保留已持久化的待核对记录。标签、发布、生产部署和付费调用均未执行。
