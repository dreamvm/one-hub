# 用户弹窗退出时的焦点恢复

2026-10-04，基线 main `e232ade20a2ea20af6a19429603c08a944e341be`（PR133 已合并）。
本项只处理用户页删除、编辑、增减额度弹窗关闭时的焦点警告。

## 复现与最小改动

本机真实 Go/SQLite 合成账号环境中，从行菜单打开上述弹窗再取消，Chromium 报告
`aria-hidden` 隐藏区域仍包含已恢复的行操作按钮焦点。源码核对：MUI Dialog 默认
`closeAfterTransition=true`；FocusTrap 在 open 变为 false 时恢复焦点，而 ModalManager
等退出动画结束才解除背景隐藏。警告与 MUI 的[既有问题](https://github.com/mui/material-ui/issues/43106)
一致；本项目结论另有旧新浏览器对照，不仅依据上游讨论。

三处显式设置 `closeAfterTransition={false}`，让关闭提交解除背景隐藏，避免焦点在退出动画期间
留在隐藏页面中。保留过渡动画、自动聚焦、打开期间的焦点限制与关闭时焦点恢复；不手动 blur，
不删除 aria 属性，不修改共享 Dialog 默认值、业务接口、权限或数据。背景隐藏及滚动锁在关闭提交时解除，
不再等待淡出动画；动画 DOM 仍在结束后卸载。此设置含义见
[MUI Modal API](https://mui.com/material-ui/api/modal/)。编辑组件也用于新增用户，因此覆盖其关闭行为。

先前“等菜单退出再打开弹窗”和“Popover 换 Menu”两种尝试均在新浏览器文档中失败，已撤回。
同一文档可能去重警告，所以每个最终浏览器场景刷新文档。瞬时 focus 事件发生时的隐藏状态
不能单独代表 React 关闭提交完成后的状态；组件回归断言关闭提交完成、退出动画尚未结束时
焦点所在页面已可访问，并由真实浏览器检查警告。
