# OIDC 声明和同名关联

已验证的subject如果已绑定启用账号，继续登录该账号；资料中的用户名改变或与另一账号同名不移动绑定。未知subject不得只凭用户名声明登录或覆盖已有账号。用户名未占用且注册开启时才允许新注册。

state、id_token和必需用户名按字符串检查；缺失、错误类型或空白必需字段稳定拒绝。注册资料email/displayName/avatar允许缺失/null，存在时要求字符串。已有绑定登录不依赖可选资料。保留原OIDC verifier的签名、issuer、audience和有效期检查。

兼容变化：未绑定或已解绑的本地账号不能再靠同名自动关联。当前产品没有独立安全的OIDC绑定界面；需核实身份后另行建立绑定流程，不能恢复不安全的同名登录来兼容。正常已绑定登录、新账号注册和关闭注册规则有合成签名token对照。

查询命中后还须按Go字符串精确比较原始subject，避免数据库大小写不敏感或忽略尾空格的排序规则把不同身份视为相同。SQLite的NOCASE/RTRIM夹具复现了该问题，正常精确匹配对照保留；未把该夹具描述成MySQL实测。

本批没有变更数据库查询或schema。subject唯一性、issuer切换的历史身份迁移仍需下一步独立核查；不宣称OIDC持久身份模型已全面完成。
