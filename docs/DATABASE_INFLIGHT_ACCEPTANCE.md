# 请求中途数据库故障与存活进程恢复

分支 `codex/database-inflight-acceptance` 基于已合并 main `53be6eb04942814f812d756dfbd809bd553e1b66`。
独立验收继承 PR #83 的有限/无限令牌、JSON/SSE 和有界上游暂停机制。只改变隔离 smoke，应用账务逻辑保持原样。

## 实际故障与判据

现有模型测试已覆盖事务写入失败和重新连接，但不能替代真实候选进程中数据库不可用的请求路径。本项在运行自己的 MySQL+Redis 或 PostgreSQL+Redis 容器时：

1. 正常请求确定费用；确认新请求已经上游接纳、有唯一归属的 reserved 收据、用户与有限令牌预留一致。
2. 停止本次创建的数据库并确认容器未运行；再释放模拟上游的完整用量。Redis 和网关进程保持存活。
3. 读取该合成网关最多 500 行日志，只计数固定的终局持久化失败诊断，不打印日志。必须新增一次失败，不能仅凭容器停止推断数据库写入失败。
4. 重启数据库；保留网关进程，让既有每 15 秒恢复任务处理它暂存的确定终局。最多等待 45 秒，核对正常响应、单一上游调用、最终消费收据、用户与令牌账目、消费日志和渠道统计。
5. 后续正常请求必须仍以相同费用结算。finally 恢复本次故障目标；外层清理该运行的容器、卷和内部网络。

四种组合（有限/无限 × JSON/SSE）分别在两个数据库执行，原 Redis 中途及请求前故障控制继续保留。SSE 暂停位于上游首个内容块刷新后，不声称故障瞬间客户端已收到该块。

## 证据边界

本地 Python 21 项、语法检查及离线工作流策略验证通过；真实数据库中途故障及恢复尚待准确候选 CI，不能将离线断言测试当作容器验收。
这是验收覆盖，不包含应用安全修复，没有新增安全修复独立审阅周期。

已有 SubmitQuotaTerminal 会先保留不可变的进程内确定终局快照，持久化成功后由 pending 收据恢复。此测试只证明网关进程存活时的恢复；意图落库前同时崩溃仍会丢失内存证据并留下 reserved 待核实。网络分区、并发负载、历史真实账目、生产备份及恢复点仍需独立验收。
不接触真实服务、生产数据或付费上游，没有标签、镜像发布或部署。
