## 修复边界

最终结算原来直接做浮点到整数转换、整数乘加和折扣调整，非法负值或溢出可能成为零或小正费用。
共享计算现在验证原始用量及明细、价格、服务次数，检查转换与整数乘加。
无效计算返回明确的内部负值标记，Consume 拒绝账务变更并保留原预留，记录错误。
这不是自动恢复机制；需要后续持久化账本处理故障及待核对请求。

- 正常按 token 向上舍入、按次截断与最小正费继续有效；只有输出定价且没有输出时不产生费用。
- 缓存折扣先计算保留的 token 数，避免极小正倍率在 `ratio - 1` 中消减为免费。
  倍率恰为零的免费缓存仍可为零费。该稳定计算也消除原浮点消减造成的边界舍入偏差。
- 按次计价是否发生用量依据原始用量，不能被缓存折扣归零；原始零用量仍退款。
- 附加服务费用独立于 token 是否为零；正单价和正单位倍率下溢时保留最小一个计费单位。
- Responses 记录附加服务时逐项保存类型，同一服务的不同规格分别计数和定价。
  单类型仍沿用原 metadata key；额外规格使用 `service|type` key，日志 UI 的通用列表仍可展示。
- 每次计算清空上次的附加费用快照，避免复用费用。
- Realtime 合并验证完整快照后才替换累计值，保存全部用量明细及显式额外 token，拒绝部分合并和溢出；
  转换快照不会反向修改累计事件。
- 后台任务保存的 Quota 使用与实际结算相同的计算，避免微小按次或按 token 任务的退款基数偏差。
  后台退款事务和幂等仍属下一独立批次。

## 验证

旧源码回归复现非法算术、仅服务费用归零、Realtime 明细/map 丢失与无效事件部分写入、
任务保存费用不一致、附加费用快照复用。正常折扣、免费、零用量与按次截断对照保留。
一次独立只读审阅发现混合附加服务类型、极小正值消减/下溢及按次缓存折扣三个边界；
主代理分别建立失败回归并修复，重跑相关验证。

相关 model/types/relay 与既有协议/控制器包的 race、vet、后端及供应商编译、工作流策略、
actionlint、隐私与历史密钥扫描通过；本地隐私测试的 Docker 项由远端 CI 验收。
最终提交 CI、合并及隔离镜像证据分别记入 PR 和 NEXT_RELEASE.md。

没有 schema 迁移，不推断历史错误费用，也不执行历史补扣。
未知附加服务或未知图像规格的价格仍沿用原映射行为，本批没有新增价格表。
上游漏报用量、重复事件、各供应商转换前的用量真实性及持久化恢复仍有独立边界。
回退会恢复原费用缺口；不能把代码回退当作历史账目修复。
