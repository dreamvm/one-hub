# 支付对话框生命周期

## 触发条件与最小修复

充值页的关闭回调每次重绘都会改变。旧PayDialog把回调作为创建订单effect依赖，
可能重复发起创建；关闭时只清理当时保存的interval，晚到的创建响应仍能启动轮询，
卸载也未清理。旧状态响应还能在重新打开后把新订单窗口显示为支付成功。
这些证据证明前端多余请求及显示错误，不证明重复扣款或后端重复入账。

改为按open、金额及网关控制一轮生命周期，最新关闭回调用ref读取；
关闭按钮、卸载或参数变化会清理计时器并使该轮迟到响应失效。
状态查询完成后再安排下一次3秒查询，避免慢请求重叠；成功后停止。
查询失败保留支付内容并提示重试，创建结果不明时停止并提示先核对记录，不自动重发订单。
GET/POST表单跳转、手动跳转、二维码和主题保持兼容。不取消服务端订单，不改变账务状态。
