# 延迟支付与渠道停用

本地三小时过期只关闭本地订单展示状态，没有撤销支付平台订单。因此，签名、金额、币种、原渠道与流水归属均验证通过的延迟成功通知，可以将pending或closed订单在同一事务内结算一次。已带结算标记、冲突流水、failed或无法证明已入账的历史success仍拒绝自动补款。

创建订单继续只读取启用且未删除的渠道。回调单独按原UUID读取保留配置（包括停用与软删除），用于处理已发起的支付；不跳过签名验证，不借用其他渠道配置，也不会重新开放新订单。停用/软删除不是支付凭据撤销操作；发生凭据泄露时仍须在支付平台撤销或轮换对应密钥并核对未完成订单。

测试覆盖正常、关闭、停用、软删除及其组合；错误金额、签名、渠道、历史标记与日志故障均不入账；关闭与并发回调后最终只记一次余额和日志。相关SQLite/PostgreSQL本地专项通过，精确候选CI/MySQL另记NEXT_RELEASE。

不对历史歧义订单猜测补款，不恢复已硬删除配置，不尝试历史未知密钥。无schema变更。回退会再次拒绝合法延迟通知；没有发布或部署。
