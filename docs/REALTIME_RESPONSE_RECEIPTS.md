# Realtime 已标识响应的连接内计费收据

调查与旧新对照基线为 main `5f0a7fc8`，交付更新至仅补充台账的 `81058877`，
六个源码/测试文件的补丁哈希保持不变；不依赖未合并的 Rollup/Vite。
本项处理上游相同 `response.id` 的 `response.done` 重放及冲突用量。
[官方事件定义](https://platform.openai.com/docs/api-reference/realtime-beta-server-events/response/done)
区分响应身份和事件身份，并将 response usage 定义为该响应的用量；不同 event_id
不能使同一响应再次收费。此项不是完整 Realtime 恢复计费交付。

## 行为与边界

- OpenAI 及继承该实现的渠道，从上游 response.id 生成内部元数据，客户端同形帧和 usage
  JSON 中的伪造身份不能进入计费。元数据不写入协议 JSON，也不改变转发帧。
- 每个 Quota/预留范围保留收据；同 ID 同快照只计一次，同 ID 冲突在累加前拒绝并结束
  连接，结算已有确认累计。不同 ID 即使用量相同仍分别计费；不同连接的相同 ID 不互相去重。
- 比较包括所有 token/detail 字段及内部 ExtraTokens，不能只序列化公开 usage 而遗漏额外
  计费值。输入先验证、完整合并后才记收据，非法或溢出输入不污染后续有效报告。
- 保留累计后取整、按次每会话一次、免费及零倍率、有限/无限令牌语义。续额失败仍保留
  已发生用量并关闭上游，不能因去重而丢弃已发生费用。
- 收据仅保留 ID/快照的 SHA-256 值，不保存任意长度的上游 ID/对象。每连接最多保存
  16,384 个不同 ID，不淘汰旧项。第 16,385 个新响应的已报告用量先计入，随后停止连接；
  收尾按全部已知用量结算，之后的回调不能继续累计。客户端需重新建立会话。
- 初始帧与供应商 worker 串行调用；最终结算仍等待两个 worker 退出。
  匿名旧格式不能按内容哈希去重，否则会吞掉合法同价多轮，因此保持逐事件累计。

## 证据

旧版实际 localhost WebSocket + 临时 SQLite 回归：同事件重放、换 event_id 重放、首帧
重放都把 7 单位记成 14；同 ID 冲突没有拒绝。两个正常对照（不同 ID 同价、匿名多轮）
通过。首次测试夹具在失败退出后未等待 handler，产生全局配置清理竞争；修正等待后，
旧版仍为上述 4 个失败/2 个通过，race 不再报告竞争。

候选的 6 个真实转发场景通过，包含客户端伪造用量不得入账。模型控制覆盖价格、账户
模式、连接身份隔离、内部额外用量、非法快照及收据上限。Realtime 相关两包专项共
59 个节点、53 个叶子通过；项目规定 model/types/gemini/claude/requester 与受影响 relay
包的 race 回归、工作流策略、相关 vet 及 provider/relay 编译通过，Go 为 1.25.14。
所有测试有超时，只用合成数据、临时数据库、localhost 随机端口；没有真实上游调用。

全新独立只读审阅覆盖 6 个源码/测试文件，补丁 SHA-256
`f4cfb306723a487432a6c4dd15ea9d4a69481a6adfd2c3531ff49185240ab94b`。
审阅者另建临时副本，禁用依赖网络下载，复跑模型与 WebSocket 控制，并增加解析等价、
续额失败重放和溢出不污染的临时控制；未发现可验证的存活绕过或阻断性回归。
首次 sandbox 拒绝回环监听，升级工具权限后的隔离重跑通过；不是无条件忽略失败。
准确候选 CI、合并和镜像验收须由后续记录确认，不能以本地或独立测试代替。

## 继续开放

收据是连接内状态，不能恢复进程崩溃前尚未持久化的逐响应用量。缺失/null usage、匿名
响应的幂等、异常结束时未报告费用、独立音频转录及运行中崩溃恢复仍开放。冲突快照
没有被当作更正金额自动覆盖；有歧义的费用仍需后续规则与可恢复证据，不能由本项推定。
现有持久终局账本仍只恢复已确定的 pending 意图，reserved 不按年龄自动退款。

另已发现首帧错误路径仅检查主 token 计数，可能遗漏正 extra/audio 费用；列为下一独立
修复，不由本项隐含关闭。回退本项会恢复重复计费；无 schema 变更、标签、镜像发布或部署。
