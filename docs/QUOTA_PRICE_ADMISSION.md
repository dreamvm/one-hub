## 问题与新行为

普通预扣原来把零估算当作无需准入，把负估算跳过实际预扣。关闭固定预扣、
微小按次价格、仅输出收费等配置可能让付费上游调用绕过当前余额检查。
图片数量直接参与整数乘法，负数与极大值也可形成无效估算。

共享 `PreQuotaConsumption` 现在验证原始价格、分组倍率、有效倍率和估算：
拒绝负数、非有限值、有效价格下溢与整数范围外的结果，并检查固定预扣的整数加法。
付费估算舍入为零时至少预留 1 个内部额度单位；此下限是准入预留，不是新的最终收费规则。
Realtime 复用此边界。明确免费的模型及零倍率分组无需预留。
图片生成、编辑、变体共享的计数函数在乘法前检查数量。

保留按次价格的既有截断、按 token 费用的向上舍入和零实际用量释放预留。
实际费用超过估算时继续收取实际费用，允许余额体现欠额；下一个付费请求不得因此放行。
本批不把预留误写成硬成本上限，不改变最终额外用量、附加服务或后台退款算法。

## 验证与限制

- 新增模型边界回归：原实现 11 个非法估算、12 个零估算付费分支及免费分组对照失败；
  其余拒绝/正常/实际超额对照通过。图片负数量在原函数复现未拒绝。
- 修改后模型、图片估算、Search 上游前拒绝、Realtime 对照通过；非法和合法极大图片数量均检查。
- 相关包 race、vet、主程序/供应商编译、工作流策略和 actionlint 通过。
  独立只读审阅未发现本批范围内可验证绕过或回归，并独立运行模型/图片/Search 回归。
- 本地使用临时 SQLite，已有三数据库事务套件与真实 Redis smoke 由对应候选 CI 验收。
  远端 CI、合并与镜像状态在 NEXT_RELEASE.md 和 PR 中分别记录，不使用前一候选结果替代。

没有数据库迁移；回退代码会恢复原来的准入绕过。最终收费的完整算术、附加价格、
持久化幂等恢复、后台退款与支付仍独立开放，不能据此宣布 C1/C2 全部完成。
