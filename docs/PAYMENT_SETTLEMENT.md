# 支付订单入账事务

经过网关验签的回调进入 `SettleOrderPayment`，按持久订单记录加写锁，核对原支付渠道后，把用户余额、分组晋升、充值日志、订单成功状态、网关流水号及 `settled_at` 一并提交。此路径不使用内存 batch 队列。只有提交成功才返回协议成功回执，数据库错误可由支付平台重复通知重试。

同一订单、同一渠道、同一流水号且已有结算标记的回调只返回成功，不重复充值；不同流水号或不确定终态返回失败并需核对。不同订单即使金额相同仍独立入账。Redis 分组缓存提交后尽力清除，数据库账目不会因缓存故障撤销。平台重试有期限，不代表无限自动恢复，超过期限需核对平台账单后处理。

此批修复同一订单事务边界。金额、币种、商户身份和跨订单流水绑定、延迟支付事件、关闭订单、停用配置及创建订单路径继续单独修复。旧版遗留成功订单没有本次事务标记，不能证明已到账，不自动补款；历史问题需与银行/平台和本地账目核对。当前版本仍不能作为全支付流程验收完成依据。

验证使用虚构账户和签名：易支付、Stripe 的控制器回调覆盖成功、失败、不相关事件、重复和签名错误；四种网关回执有单元对照。三数据库矩阵运行 `^TestQuotaTransactionPayment`，覆盖 batch 开关、16 并发、错误渠道、故障回滚、新连接重试、等额独立订单、非法额度与旧终态。支付宝和微信完整签名回调在后续协议批次补齐。

回退前停止支付回调写入并核对在途通知。新增结算列可兼容旧表，但旧应用不遵守同一事务及回执约束，禁止新旧版本混合承担此路径。此次不修改支付平台配置、不发起真实交易、不发布镜像或部署。
