# 兑换码事务与终态

兑换码领取、用户余额、分组晋升和充值日志在同一个数据库事务中完成。条件写入领取记录，避免跨进程重复领取；批量余额开关不改变此路径，任何数据库步骤失败都会回滚，允许用户安全重试。

- 只有启用、额度大于零、没有历史兑换时间或兑换人标记的记录可以领取。旧表中未使用记录的 NULL 标记仍可正常兑换。
- 已使用记录不能通过管理员状态切换或过期的编辑表单重新启用。未使用记录仍可禁用、启用、修改名称和正数额度。
- `user_id` 继续表示创建人；新增 `redeemed_by` 记录本次兑换人。无法可靠推断的历史兑换人不回填。
- 余额到账后只计算一次累计额度用于分组晋升。提交后清除 Redis 分组缓存；缓存清理失败不撤销已经提交的充值，旧缓存按既有 TTL 过期。

历史数据若已存在“启用但有使用标记”的记录，将拒绝再次领取，需要根据历史账务核对；不会自动清空标记或再次补款。历史重复充值也不自动扣回。

验证覆盖正常兑换、同用户/跨用户并发、批量开关、过期编辑、余额/日志/晋升失败回滚、溢出、删除用户、历史标记、NULL 兼容、HTTP 入口及 Redis 故障。事务用例通过 `^TestQuotaTransaction` 纳入 SQLite、MySQL、PostgreSQL CI。

回退应用版本前应停止兑换写入并核对正在处理的请求。新增列兼容旧结构，但旧应用会恢复原来的领取竞态和重开风险，不能混用新旧版本承担兑换流量。此次不包含支付回调事务，支付路径单独修复验收。
