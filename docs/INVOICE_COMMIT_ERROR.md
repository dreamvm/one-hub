# 月账单提交失败的错误返回

## 问题与修复

`InsertStatisticsMonthForDate` 原先检查汇总 SQL 和生成历史的写入错误，却忽略
`tx.Commit().Error`，提交失败仍写成功日志并返回 nil。管理员生成/更新接口根据返回值
报告成功，定时任务也无法记录这一错误。启动 goroutine 原本忽略整个函数的返回值，
本项不将其改写为已具备错误观察或自动恢复机制。

最小修复只在提交后检查错误，失败立即返回，不再记录成功；不自动重试、不猜测提交结果，
不改变账单汇总、预留额度或支付状态。此项依赖日期类型修复 PR #111，独立提交与验收。

## 验收边界

该失败夹具证明 SQLite 确定回滚的提交错误。MySQL/PostgreSQL 的延迟提交失败、
连接在提交确认时丢失导致的结果不确定、进程崩溃和跨进程恢复不由本测试证明。
对这类不确定情况只返回错误，不能推断全部回滚或盲目重试；应先核对持久化数据。
未改实际数据库结构或真实历史账单，未部署或执行真实付费调用。

回滚此代码会恢复错误成功返回；函数签名和数据库结构无变化。
独立审阅、准确候选 CI、合并和合并后验证在实际完成时追加，不能以本地测试代替交付。
