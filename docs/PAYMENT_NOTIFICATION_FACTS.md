# 支付通知事实与订单绑定

验签不等于可以充值。网关先提取经过签名保护的支付事实，订单事务再核对原渠道、订单金额（整数分）、币种，以及协议提供的本地用户标识。任何不匹配、缺失必需字段或不确定状态都不能入账。

| 网关 | 核对来源 | 正常行为 |
|---|---|---|
| 易支付 | 签名、pid、已配置的支付类型、money | 未指定 pay_type 的收银台仍可选择类型；协议无币种字段，币种采用管理员所配置的结算币种，不能声称独立验证上游币种 |
| 支付宝 | 当前配置的公钥、app_id、total_amount | 重启后回调独立初始化；SUCCESS/FINISHED 可入账；优惠券不以 buyer_pay_amount 替代订单总额；配置未提供独立 seller_id，不推断它 |
| 微信 | 当前商户证书、解密、appid、mchid、amount.total/currency | 优惠券不以 payer_total 替代订单总额；商户密钥/序列号/APIv3Key 变化重建证书下载器并停止旧刷新任务 |
| Stripe | 当前 webhook 签名、paid 状态、amount_total/currency、metadata.user_id | 已签名 unpaid 完成事件只确认接收，不充值；completed/async_payment_succeeded 的 paid 事件进入事务；通知订阅配置仍需下一批完善 |

缺少签名密钥不能退化成空密钥验签。重复查询/表单字段不得由验签和业务取值分别选择。金额不使用浮点容差匹配，文本金额只接受正数和最多两位小数，遵守现有订单 decimal(10,2) 范围；数据库中的两位金额转换成整数分后比较。

`order_payment_claims` 使用渠道 ID 和完整网关流水号的哈希作为唯一键，同一流水只能归属一笔本地订单。领取记录与充值同事务，失败不占用流水。升级前及软删除订单中的已有流水归属也参与检查；有历史冲突时拒绝自动认领，不自动补款或扣款。

四种网关验证使用临时 RSA 密钥、本地签名/加密通知及模拟证书响应，不接触真实支付。SQLite/MySQL/PostgreSQL 矩阵覆盖共享入账与每个网关的正常、优惠、缺失/不匹配事实、错误签名、历史归属及微信凭据轮换；具体提交和 CI 结果记录于 NEXT_RELEASE.md。

本批仍不完成订单创建算术/外部请求时机、关闭或停用后的延迟通知、Stripe webhook 订阅和历史财务核对。混合运行旧版本会绕过这些约束；回退前应停写并核对在途回调。微信首次初始化/轮换需要访问官方证书接口，失败返回可重试错误；普通已缓存通知不逐次下载证书。
