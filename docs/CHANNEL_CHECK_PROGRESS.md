# 渠道检测流式结果显示

2026-10-02，从已验收 main `9534294a774f6c1b680662613497edff749772dd` 开始。
这是现有 Axios 1.18.0 的页面兼容修复，不升级依赖，也不关闭其公告匹配。

## 问题与最小改动

`ChannelCheck` 的批量检测请求使用 `responseType: 'text'` 和 Axios 的
`onDownloadProgress`。Axios 将原生进度事件包装在 `event` 字段中；旧页面直接读取
包装对象的 `currentTarget.response`，导致结果显示失败。节流回调执行时，原生
`currentTarget` 也可能已清空，不能只增加一层 `event.currentTarget`。

页面改为从 `progressEvent.event?.target?.response` 读取累计文本，并在请求成功完成后
处理最终 `response.data`，覆盖没有进度通知或最后一段尚未通知的情况。既有按模型更新
结果的规则保持，累计文本再次解析不会添加同模型重复结果。无文本的通知跳过，分段中
尚未完整的 JSON 沿用原行为，等待后续累计文本。

加载状态在 `finally` 中释放，覆盖非 200 分支的提前返回；现有错误提示保持。
未修改渠道选择、服务器请求、收费、Axios 工厂、依赖文件或页面主题样式。
