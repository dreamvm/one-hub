# Realtime 缺失用量的待核对边界

基线：PR #75 已合并 main `8351770c6eb044f45be0fc3eb3faf3aff27ba49f`。
分支 `codex/realtime-missing-usage`，不依赖未合并的 Rollup/Vite 草稿。
本项处理明确供应商完成事件缺少报告；通用异常结束和崩溃恢复仍开放。

## 缺陷与保留行为

供应商 `response.done` 的 usage 缺失/null 时，旧处理器不触发计费回调，
收尾将零或已知部分累计写为确定消费。整个 response 缺失/null 则提前报错，
首帧会退款重试，主循环仍结算已知部分。这些事件不能证明实际总费用。

显式 `{}` 仍是已有协议下的零用量对象；完整报告保持既有收费。
没有工作事件的握手控制不变。客户端消息及 usage JSON 不能设置内部标志。
本项没有改变真实上游的协议要求，也没有新增补扣、自动退款或人工核销规则。

## 最小共享边界

- OpenAI 解析器为缺失报告生成 `json:"-"` 的 `MissingUsage` 元数据；
  response 缺失仍保留原 `invalid_response` 错误及拒绝结果。
- 首帧与 WSProxy 在处理该错误前调用计费回调；回调固定待核对意图，停止上游并拒绝继续。
  首帧不再重试其他渠道。其他普通错误/用量的原有处理顺序不变。
- 复用 Quota 首次终局选择及不可变快照重试。收尾将账本转为 `reconcile`，
  保留预留和原用户/令牌归属，不修改余额、统计、消费日志、最终费用或 outcome。
- `reconciliation_data` 保存版本、固定原因、已接受的用量/extra、当时计价及已知部分金额。
  已知金额不是最终费用；不能计算则保留未知。响应 ID 仅存 SHA256，
  不保存原始事件、提示词、音频、凭据或原始响应 ID；序列化上限 64 KiB。
- 同一证据重放幂等；冲突证据、普通 Consume/Undo、续额和 Finalize 均不能覆盖该状态。
  既有恢复任务重试失败的快照写入，但不自动结算 `reconcile`。

## 迁移、回退与未覆盖范围

应用启动的可检查 AutoMigrate 增加 TEXT 列；本地旧账本迁移控制保留原预留及余额。
必须先迁移再启动新节点。旧账本代码不会自动处理 `reconcile`，回退保留列和证据，
不能将其改成 `pending`、删除或按年龄退款；混合运行不代表新解析边界全面生效。

快照未持久化前进程崩溃仍只留下 `reserved`；数据库长期不可用的容量/网络分区、
没有完成事件的断连、报告中非法计数、跨连接报告归属、历史金额核对及人工处置仍需后续专项。
没有为未知金额猜测账单，没有关闭 RC8 阻断项，也没有标签、镜像发布或生产部署。
