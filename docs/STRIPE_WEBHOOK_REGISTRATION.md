# Stripe webhook 注册与复用

注册使用按渠道密钥初始化的客户端，不修改进程级Stripe key。新端点订阅checkout.session.completed和checkout.session.async_payment_succeeded，并固定当前SDK对应的API版本；本批不升级依赖。

按完整回调URL查找已有端点，保留本地签名密钥（Stripe列表/更新响应不再返回它），保留其他订阅并补充缺失成功事件。通配符订阅可复用。版本兼容与当前SDK一致，允许同一版本系列的不同日期版本。重复URL、缺失签名密钥、停用端点、不兼容版本等情况报错交由核对，不猜测端点或密钥。

若外部创建成功而本地保存失败，返回明确错误并恢复调用对象的配置；远端端点不会自动删除，需人工核对后再注册。本地AddPayment仍按原流程清理失败的本地配置。这里没有跨平台原子事务，不能宣称自动恢复外部孤立端点。

CreatedPay目前仅在新增渠道时调用。升级不会自动修改既有Stripe账户上的事件订阅；发布前需逐个核对既有端点、签名密钥及异步成功订阅，并单独授权实际平台操作。

15个合成本地HTTP/数据库用例覆盖新建、复用、签名密钥保留、通配符、追加事件、不同账户key隔离、兼容版本及外部/数据库失败。旧实现正常新建控制通过，其余相关回归失败；SDK使用Bearer鉴权，初始测试夹具纠正为该语义后才记录旧版证明。独立审阅确认版本限制过严，新增失败对照后修正。

无schema或锁文件变化，未访问真实Stripe；回退会恢复密钥覆盖和异步事件缺失。CI/MySQL/镜像验收以NEXT_RELEASE的准确提交记录为准。
