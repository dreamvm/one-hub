# 中继令牌的当前授权状态

## C1a：令牌对象从数据库读取

`GetTokenModel → CacheGetTokenByKey` 保留原有调用接口，但每次读取数据库当前令牌行。
Redis 中旧的完整令牌对象不再决定 `remain_quota`、`unlimited_quota`、状态、过期时间及分组等字段。
这样即使额度写入未失效缓存、缓存失效失败，或者较早的缓存填充晚于数据库变更完成，
旧对象也不能覆盖已经持久化的授权状态。软删除、换 Key 或数据库读取失败均拒绝授权。

新签名令牌和旧 48 字符令牌共用该入口。原有签名、旧令牌集合检查和用户状态检查继续执行，
不改变已耗尽令牌在免费/透传入口也被拒绝的既有规则。正常有限令牌、无限令牌及数据库中
已恢复为可用额度的有效令牌仍可使用。没有修改 API 返回格式、令牌生成或数据库 schema。

启用 Redis 时，每次令牌授权增加一次按唯一 Key 的数据库查询，也不再使用旧缓存填充路径的
singleflight 和 1 秒等待包装；这是一项容量与延迟取舍，未做生产压测或数据库延迟测试。
数据库不可用时不会退回旧令牌对象继续授权。其他用户状态、用户分组及用户余额缓存策略保持原实现，
本项不宣称解决这些缓存的全部一致性问题。旧 token 缓存对象可以按原 TTL 过期，无需迁移或清空 Redis。

## 验证范围

新增 `model/token-authority_test.go` 使用临时 SQLite 和 go-redis 命令 Hook，运行真实 Redis store
与 MessagePack 缓存序列化逻辑；Hook 只模拟 GET/SET/旧令牌成员检查，禁止网络访问。
该夹具不是实际 Redis 服务，也不验证 Redis 故障切换或协议行为。

失败回归覆盖 Redis 开/关、BatchUpdate 开/关、新/旧令牌格式，以及已持久化的耗尽、
无限转有限、禁用、过期、删除、换 Key、数据库不可用；正常对照包括有效令牌、当前分组/名称、
额度恢复和零余额的无限令牌。BatchUpdate 开关用例仅证明授权读持久数据，不证明待刷盘额度已可见。
模型包既有 CI 自动运行这些离线用例；通用隔离镜像另含真实 MySQL＋Redis smoke，不能替代上述专项夹具的边界说明。

```sh
go test -race -count=1 ./model -run '^TestTokenAuthority'
go test -race -count=1 ./model ./controller ./middleware ./relay/midjourney
go vet ./model ./controller ./middleware
```

## 仍未完成的额度边界

C1a 只解决**旧令牌缓存覆盖已持久化状态**，不等于完整的有限额度上限修复。
高账户余额跳过预扣、尚未刷盘的批量计费、预扣/退款/重试生命周期、搜索子调用顺序和实时会话
仍须后续修复。并发条件更新、账户与令牌事务、实际消费超过预估及持久化失败恢复属于 C2；支付幂等属于 C3。
后台任务的历史退款语义不能未经账目核实就扩大。

回退本补丁会恢复旧缓存授权问题；没有 schema 回滚步骤。PostgreSQL、生产容量和真实上游未验收。
